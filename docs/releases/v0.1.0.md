# PopChoice v0.1.0

First stable platform release.

## Highlights

- Promoted PopChoice from the beta release line to the stable `v0.1.0` release line.
- Standardized long-lived Coolify `development` and `production` environments with separate shared variables, secrets, domains, and deploy webhooks.
- Documented the release flow from development validation to production promotion, including GitHub environment secrets and Coolify deployment verification.
- Kept the recommendation platform foundation from `v0.1.0-beta.0`: async recommendations, accounts, recommendation history, movie memory, TMDB catalog maintenance, BullMQ workers, and operator surfaces.
- Kept production on prebuilt GHCR images for web, workers, Bull Board, backoffice, docs, and Storybook.

## Deployment Notes

Coolify resource variables should set:

```txt
APP_VERSION=0.1.0
APP_CHANNEL=development
DEPLOYMENT_ENVIRONMENT=development
IMAGE_TAG=development
```

for the development environment, and:

```txt
APP_VERSION=0.1.0
APP_CHANNEL=production
DEPLOYMENT_ENVIRONMENT=production
IMAGE_TAG=production
```

for production.

Keep secrets in Coolify project/environment shared variables and GitHub environment secrets, not in the Compose file.

## Verification

- Confirm `/api/health` returns `200` for the deployed web service.
- Confirm `/api/build` reports `version: 0.1.0` and the expected `channel`.
- Confirm a recommendation can be created and completed.
- Confirm workers, Redis, PostgreSQL, and operator surfaces are healthy.
